# MNT-012

## Título
Impedir que un Plan quede inutilizable con `CantidadPosiciones = 0`

## Tipo
VALIDATION

## Prioridad
MEDIUM

## Problema
Un plan sin secciones (o con una lista vacía) produce `CantidadPosiciones = 0`. Ese plan se guarda
sin error, aparece en la lista como normal, pero es imposible asignarle equipos o ubicaciones y su
pantalla de detalle falla.

## Objetivo
Que el sistema no permita crear ni dejar un plan en un estado matemáticamente inválido.

## Comportamiento actual
- `NumeroUtilitario.MCM(decimal[])` devuelve `0` para un array vacío.
- `PlanMantenimientoController` calcula `_.MCM = NumeroUtilitario.MCM(secciones) * _.Intervalo` → `0`.
- `PlanMantenimientoLogica` calcula `CantidadPosiciones = Convert.ToInt32(MCM / Intervalo)` → `0`.
- Efectos verificados:
  1. `PlanMantenimientoEquipoController.Validar(model, plan)` compara
     `PosicionInicio >= CantidadPosiciones` → siempre verdadero → el mensaje es
     *"La posición maxima es -1"*, sin explicar la causa real.
  2. `PlanMantenimiento/Ver.cshtml:181` evalúa `item.PosicionActual % Model.CantidadPosiciones`
     → **`DivideByZeroException`** si el plan llegara a tener asignaciones.
  3. Con `Rutina = true` y un array de secciones vacío enviado explícitamente,
     `entidad.Secciones?.Max(x => x.Intervalo)` lanza
     `InvalidOperationException: Sequence contains no elements` → error 500 sin manejar.
     (Con el formulario normal `Secciones` llega `null` y el operador `?.` lo evita.)

## Comportamiento esperado
- No se puede guardar un plan sin al menos una sección, con un mensaje claro.
- O bien, si el negocio permite planes "borrador" sin secciones, el plan queda marcado como
  incompleto, no se puede asignar y la interfaz lo explica.

**DECISIÓN MENOR**: ¿debe permitirse guardar un plan como borrador sin secciones? Registrar en
`legacy/CURRENT-STATE.md` si el propietario lo prefiere.

## Riesgos
- **MEDIO**: pueden existir planes con 0 secciones en producción. Si se añade la validación al
  guardar, esos planes **no podrán editarse** hasta añadirles una sección. Hay que diagnosticarlos
  antes y decidir cómo tratarlos.
- Cambiar `NumeroUtilitario.MCM` afecta a otros usos: no lo toques sin revisarlos.

## Propuesta de solución
1. Diagnóstico: contar planes con `cantidadposiciones = 0` y planes sin filas en
   `planmantenimientoseccion`.
2. Validar en `Validar(Nuevo)` y `Validar(Editar)`: al menos una sección, con el mensaje
   *"El plan debe tener al menos una sección para poder programarse."*
3. Blindar la lógica: si `CantidadPosiciones` calculado es `0`, no persistir y devolver error.
4. Blindar `Ver.cshtml` contra la división por cero (mostrar `-` en lugar de fallar).
5. Sustituir `Max()` por `DefaultIfEmpty(0).Max()` en el cálculo de `Rutina`.

## Tests requeridos
- Guardar un plan sin secciones → `400` con mensaje claro (hoy guarda un plan inservible).
- Guardar con una sección → funciona igual que hoy.
- POST manipulado con `secciones` como array vacío y `rutina=true` → `400`, no `500`.
- `Ver` de un plan preexistente con `CantidadPosiciones = 0` → se renderiza sin excepción.
- Planes válidos existentes: sin cambios de comportamiento.

## Criterios de aceptación
- [ ] Diagnóstico de planes afectados entregado.
- [ ] No se pueden crear planes con `CantidadPosiciones = 0`.
- [ ] Ningún camino produce un error 500 sin manejar.
- [ ] `Ver` tolera los planes inválidos preexistentes.

## Fuera de alcance
- Corregir o eliminar planes existentes con 0 secciones.
- Recalcular posiciones al cambiar la configuración (`MNT-016`).
