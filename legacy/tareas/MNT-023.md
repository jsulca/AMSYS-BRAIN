# MNT-023

## Título
Optimizar la carga de detalle de Hoja de Ruta

## Tipo
PERFORMANCE

## Prioridad
MEDIUM

## Problema
`HojaRuta/Ver` carga en memoria todas las secciones de la hoja de ruta y, para todas ellas, todas sus
tareas, materiales y servicios, sin paginación ni límite. En hojas de ruta grandes la pantalla se
degrada de forma proporcional al contenido.

## Objetivo
Que el detalle de una Hoja de Ruta cargue en tiempo constante respecto al número de secciones.

## Comportamiento actual
`AMSYS.Logicas/Gestion/HojaRuta.Logica.cs` (`BuscarPorIdAsync` con `conDetalles = true`):
```csharp
List<Seccion> secciones = await seccionRepositorio.ListarAsync(new() { HojaRutaId = id });
int[] seccionIds = secciones.Select(x => x.Id).ToArray();
List<Tarea> tareas = tareaRepositorio.Listar(new() { SeccionIds = seccionIds });
List<SeccionMaterial> materiales = seccionMaterialRepositorio.Listar(new() { SeccionIds = seccionIds });
List<SeccionServicio> servicios = seccionServicioRepositorio.Listar(new() { SeccionIds = seccionIds });
foreach (Seccion item in secciones) { /* asignacion en memoria */ }
```
Observaciones:
- El patrón **evita el N+1** (4 consultas fijas, no una por sección): esa parte está bien resuelta.
- El problema es el **volumen**: no hay límite ni paginación, y `TareaRepositorio.Listar` incluye
  `Especialidad`, `TipoTarea`, `Sistema` y `Parte` para cada tarea.
- Las tres llamadas a `Listar` son **síncronas** (`.ToList()`) dentro de un método `async`, bloqueando
  el hilo.
- La vista `HojaRuta/Ver.cshtml` renderiza todas las secciones con sus tareas, materiales y servicios
  de una sola vez.

## Comportamiento esperado
- La pantalla muestra las secciones y carga el detalle de cada una bajo demanda.
- Las consultas son asíncronas.
- Se mantiene la ausencia de N+1.

## Riesgos
- **BAJO-MEDIO**: cambiar a carga diferida modifica la interacción. Si el usuario usa esta pantalla
  para imprimir la hoja de ruta completa, la carga bajo demanda le perjudicaría. **Verificar el uso
  real antes de cambiar la UI.**
- Añadir versiones asíncronas a los repositorios afecta a otros llamadores.

## Propuesta de solución
1. **Medir primero**: cuántas secciones y tareas tiene la hoja de ruta más grande en producción. Si
   el máximo es modesto, esta tarea puede cerrarse como "no necesaria" y quedar documentada.
2. Añadir `ListarAsync` a los repositorios de `Tarea`, `SeccionMaterial` y `SeccionServicio`,
   manteniendo los métodos síncronos para no romper llamadores.
3. Renderizar en la vista sólo la cabecera de cada sección; cargar el detalle al desplegar
   (endpoint `Seccion/Buscar`, que ya existe).
4. Mantener un botón "Expandir todo" para el caso de impresión.

## Tests requeridos
- Hoja de ruta con 50 secciones y 1000 tareas: la carga inicial es notablemente más rápida.
- Desplegar una sección carga su detalle correctamente.
- El número de consultas de la carga inicial no depende del número de secciones.
- La información mostrada es la misma que hoy.

## Criterios de aceptación
- [ ] Medición previa documentada.
- [ ] Las consultas del detalle son asíncronas.
- [ ] La carga inicial no depende del volumen de tareas.
- [ ] No se introduce ningún N+1.
