# MNT-039

## Título
Unificar y explicar la terminología del modo de plan (`Rutina` / Estático / Dinámico)

## Tipo
UI

## Prioridad
HIGH

## Problema
Un mismo concepto —el modo de cálculo de las posiciones del plan— recibe tres nombres distintos en la
interfaz y ninguno se explica. El control es un interruptor con dos etiquetas a los lados que no
indica cuál está seleccionada, y su efecto cambia radicalmente el comportamiento del plan.

## Objetivo
Que el usuario entienda qué elige y qué consecuencia tiene.

## Comportamiento actual
| Lugar | Cómo aparece |
|-------|--------------|
| Entidad y formulario | propiedad `Rutina` (booleano) |
| `Nuevo.cshtml` / `Editar.cshtml` | switch con etiquetas *"Dinámico"* a la izquierda y *"Estático"* a la derecha |
| `Index.cshtml` (grilla) | columna **COMPORTAMIENTO** con los valores *Estático* / *Dinámico* |
| `Index.cshtml` (filtro) | desplegable *ESTÁTICO* / *DINÁMICO* |
| `Controller.Listar` | `Rutina = x.Rutina ? "Estático" : "Dinámico"` |

Efecto real (`BR-PM-003`):
- `Rutina = true` ("Estático") → `CantidadPosiciones = max(Secciones.Intervalo)`
- `Rutina = false` ("Dinámico") → `CantidadPosiciones = MCM / Intervalo`

Ninguna pantalla explica esto. El switch tampoco resalta la opción activa: el usuario no sabe si
está en Estático o en Dinámico sin fijarse en la posición del control.

## Comportamiento esperado
- Un único término visible en toda la interfaz.
- Un control que indique claramente la opción seleccionada.
- Una descripción breve de qué implica cada modo.
- La propiedad `Rutina` del modelo puede conservarse (renombrarla implica migración), pero debe
  documentarse su correspondencia.

## Riesgos
- **BAJO**: es un cambio de presentación.
- **Atención**: renombrar la propiedad `Rutina` en la entidad exigiría migración de base de datos y
  tocaría el JavaScript que envía `'rutina': $('#Rutina').prop('checked')`. **No está incluido** en
  esta tarea.
- El filtro de la grilla envía `filtro.Rutina` con valores `"true"`/`"false"`: si se cambia la
  etiqueta visible hay que mantener el valor enviado.

## Propuesta de solución
1. **Decidir la terminología con el propietario** (`D-16`): ¿cuál de los tres términos usa realmente
   el negocio? Preguntar antes de elegir por criterio técnico.
2. Sustituir el switch por dos opciones excluyentes (radio buttons) con etiqueta y descripción:
   - *"Estático — el ciclo tiene tantas posiciones como el intervalo mayor de sus secciones."*
   - *"Dinámico — el ciclo se calcula con el mínimo común múltiplo de los intervalos."*
3. Mostrar bajo el control el valor resultante de `CantidadPosiciones` (se integra con `MNT-038`).
4. Unificar el término en la grilla, el filtro, `Ver` y `Editar`.
5. Documentar en `negocio/BUSINESS-RULES.md` la correspondencia entre `Rutina` y el término visible.
