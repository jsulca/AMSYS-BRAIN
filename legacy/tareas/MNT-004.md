# MNT-004

## Título
Corregir la generación del código de Orden de Trabajo (`COUNT + 1` produce duplicados)

## Tipo
DATA_INTEGRITY

## Prioridad
HIGH

## Problema
El código de la OT se deriva de un conteo de filas, no de una secuencia. Dos usuarios que crean o
generan órdenes simultáneamente obtienen el mismo código, y no existe índice único que lo impida.

## Objetivo
Que el código de OT sea único por empresa y año, de forma segura ante concurrencia.

## Comportamiento actual

Creación manual — `AMSYS.Logicas/Gestion/OrdenTrabajo.Logica.cs:120-122`:
```csharp
int cantidad = _repositorio.CountBy(x => x!.EmpresaId == entidad.EmpresaId && x.Anio == ahora.Year) + 1;
entidad.Codigo = $"OT-{ahora.Year}-{cantidad:D5}";
```

Generación por plan — `PlanMantenimiento.Logica.cs`:
```csharp
ordenTrabajoRepositorio.Contar(ref cantidades, ahora.Year);
foreach (OrdenTrabajo item in ordenesTrabajo)
    item.Codigo = $"OT-{ahora.Year}-{++cantidades[item.EmpresaId]:D5}";
```

Escenarios de fallo verificados por lectura del código:
1. **Concurrencia**: dos requests leen el mismo `COUNT` antes de que ninguno confirme → códigos
   idénticos, insertados sin error porque no hay índice único.
2. **Formato agotado**: `D5` desborda a partir de 100 000 órdenes en un año (produce 6 dígitos, no
   duplica pero rompe el formato).
3. Si alguna vez se borrasen órdenes físicamente, el conteo retrocedería y reutilizaría códigos.

## Comportamiento esperado

> **Alcance reducido el 2026-08-29 tras la decisión `D-03`.**
> El propietario ha decidido que los códigos **no deben ser únicos**, porque a veces la duplicación
> es legítima. Por tanto **se elimina de esta tarea la creación de un índice único**.
>

> `OrdenTrabajo.Codigo` lo **genera el sistema**, y sus duplicados no son una duplicación deliberada
> sino una condición de carrera. Esa distinción queda abierta como **`D-03b`**.

Alcance vigente de esta tarea:
- La numeración de órdenes es **atómica**: dos lanzamientos simultáneos obtienen números distintos.
- El formato `OT-{año}-{5 dígitos}` no cambia.
- **No se crea índice único** mientras `D-03b` no lo autorice.

Fuera del alcance hasta que se responda `D-03b`: garantizar la unicidad a nivel de base de datos.

3. Envolver la generación masiva en una transacción explícita (coordinar con `MNT-013`).
4. **Sólo si `D-03b` lo aprueba**: añadir el índice único `(empresaid, codigo)` y el reintento
   controlado ante su violación. Generar la migración y detenerse; no aplicarla.
