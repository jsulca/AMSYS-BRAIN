# MNT-027

## Título
Validar la configuración de secciones dentro de un Plan (duplicados y coherencia de `Nivel`)

## Tipo
VALIDATION

## Prioridad
MEDIUM

## Problema
La tabla de secciones de un plan admite configuraciones que producen comportamientos inesperados en
la generación de órdenes: la misma sección repetida, y niveles empatados que hacen que se ejecuten
varias secciones a la vez duplicando tareas.

## Objetivo
Impedir configuraciones de plan cuyo comportamiento no es el que el usuario espera.

## Comportamiento actual
`PlanMantenimientoController.Validar` comprueba, por fila, que `SeccionId`, `PrioridadId`,
`TipoMantenimientoId`, `TallerResponsableId` sean `> 0` y que `Intervalo > 0`. **No valida**:

1. **Sección duplicada**: la misma `SeccionId` puede aparecer varias veces. En
   `ComportamientoConPlanMantenimientoSeccion`, ambas filas coinciden en las mismas posiciones y, si
   tienen el mismo `Nivel`, ambas sobreviven → las tareas se copian **dos veces** a la orden
   (`BR-PM-007` copia de todas las secciones de la posición).
2. **`Nivel` sin restricción**: no se valida rango ni unicidad. El algoritmo sólo conserva
   `subSecciones.Where(x => x.Nivel == nivel)` con `nivel = Max(...)`; ante empate conserva **todas**.
3. **Coherencia `Nivel` / `Intervalo`**: nada impide que una sección de intervalo 1 tenga nivel 10 y
   una de intervalo 4 tenga nivel 1, invirtiendo la absorción que el usuario probablemente espera.
4. La UI da `value="1"` por defecto a `Nivel` en todas las filas nuevas, de modo que **el empate es
   el caso por defecto** si el usuario no lo cambia.

## Comportamiento esperado
- No se puede añadir la misma sección dos veces al mismo plan.
- El `Nivel` es un entero positivo.
- El sistema advierte cuando la configuración produce empates de nivel.

**DECISIÓN PENDIENTE** (`BR-UNK-001`, `D-11`): ¿el `Nivel` debe ser único dentro del plan?
¿Debe correlacionarse con el `Intervalo`? La semántica exacta no está documentada en el código.

## Riesgos
- **MEDIO**: pueden existir planes con secciones duplicadas o niveles empatados en producción, que
  hoy generan órdenes con tareas duplicadas sin que nadie lo haya notado. Añadir la validación
  impediría **editarlos** hasta corregirlos.
- Exigir unicidad de `Nivel` sin la decisión `D-11` podría prohibir configuraciones legítimas.

## Propuesta de solución
1. **Diagnóstico**: planes con `SeccionId` repetida; planes con niveles empatados entre secciones que
   coinciden en alguna posición. Entregar el informe.
2. Validar lo indiscutible, que no requiere decisión:
   - `SeccionId` única dentro del plan (la UI ya lo evita al añadir, pero el POST no).
   - `Nivel > 0`.
3. Añadir una **advertencia no bloqueante** en la interfaz cuando dos secciones empaten en nivel y
   coincidan en alguna posición, explicando que ambas se ejecutarán.
4. Plantear `D-11` y, sólo entonces, decidir si el empate debe prohibirse.

## Tests requeridos
- POST con la misma sección dos veces → `400`.
- POST con `Nivel = 0` o negativo → `400`.
- Dos secciones con el mismo nivel que coinciden en una posición → se guarda, con advertencia visible.
- Planes válidos existentes → se editan igual que hoy.
- El cálculo de posiciones no cambia.
