# MNT-009

## Título
Resolver el no-op silencioso: planes por CONTADOR asignados a Ubicaciones

## Tipo
BUSINESS_RULE

## Prioridad
HIGH

## Problema
`GenerarMantenimientoUbicaciones` sólo implementa la rama de UMS `CALENDARIO`. Si un plan con UMS de
tipo `CONTADOR` (o `PUNTO_MEDIDA`) tiene ubicaciones asignadas, esas asignaciones **nunca generan una
orden de trabajo** y el sistema no lo indica en ningún sitio. La interfaz permite crear la asignación
sin advertencia alguna.

## Objetivo
Que el sistema no acepte silenciosamente configuraciones que nunca producirán mantenimiento.

## Comportamiento actual
`AMSYS.Logicas/Gestion/PlanMantenimiento.Logica.cs:342`:
```csharp
foreach (PlanMantenimientoUbicacion ubicacion in planUbicaciones)
{
    if (plan.UnidadMedidaServicio!.Tipo == TipoUms.CALENDARIO)
    {
        // ... unica rama implementada
    }
    // no hay else
}
```
- `PlanMantenimientoUbicacion` **no tiene** `ContadorInicio` ni `ContadorActual`, a diferencia de
  `PlanMantenimientoEquipo`. Estructuralmente no puede soportar contadores.
- `PlanMantenimientoUbicacionController.Nuevo` **no valida** el tipo de UMS del plan.
- `PlanMantenimiento/Ver.cshtml` renderiza la tabla de ubicaciones sin columnas de contador, lo que
  sugiere que la limitación es conocida pero no comunicada.
- `TipoUms.PUNTO_MEDIDA` no está implementado para ningún tipo de objeto técnico.

## Comportamiento esperado
**DECISIÓN PENDIENTE.** Ver `CURRENT-STATE.md` → `D-06`.

- **Opción A — Prohibir (recomendada, menor riesgo)**: impedir asignar ubicaciones a planes con UMS
  distinta de `CALENDARIO`, con un mensaje claro. Ocultar el botón *Asignar Ubicación* en esos planes.
- **Opción B — Implementar**: añadir `ContadorInicio` / `ContadorActual` a
  `PlanMantenimientoUbicacion` y la rama de contador. Requiere definir qué contador aplica a una
  ubicación (`Contador` está asociado a `Equipo`, no a `Ubicacion` — **hoy no existe el dato**).

`INFERENCIA`: la Opción B exige un cambio de modelo de datos que no está sustentado por el diseño
actual. La Opción A refleja lo que el sistema realmente sabe hacer.

## Reglas de negocio involucradas

- `BR-AS-001` (asignación a equipos y/o ubicaciones) — `CONFIRMED`

## Archivos potencialmente afectados

- `AMSYS.WebAdmin/Areas/Gestion/Views/PlanMantenimiento/Asignar.cshtml`

- `AMSYS.Entidades/Gestion/Genericos/PlanMantenimientoUbicacion.cs` (sólo en la Opción B)

## Entidades involucradas
`PlanMantenimientoUbicacion`, `PlanMantenimiento`, `UnidadMedidaServicio`, `Contador`

## Riesgos
- **Datos existentes**: puede haber ubicaciones ya asignadas a planes por contador. La Opción A debe
  decidir qué hacer con ellas (bloquear nuevas y reportar las existentes, sin borrarlas).
- La Opción B multiplica el alcance: nuevo campo, migración, UI, y un modelo de contadores por
  ubicación que hoy no existe.

## Propuesta de solución (Opción A)
1. **Diagnóstico**: listar las `PlanMantenimientoUbicacion` cuyo plan no es `CALENDARIO`.
   Entregar el informe al propietario.
2. Validar en `PlanMantenimientoUbicacionController.Nuevo` (y `Editar`) que
   `plan.UnidadMedidaServicio.Tipo == TipoUms.CALENDARIO`, con el mensaje
   *"Sólo pueden asignarse ubicaciones a planes con unidad de medida de tipo calendario."*
3. En `PlanMantenimiento/Asignar.cshtml`, ocultar o deshabilitar el botón *Asignar Ubicación* cuando
   el plan no sea de calendario, explicando el motivo.
4. En `PlanMantenimiento/Ver.cshtml`, marcar en rojo las asignaciones inválidas preexistentes.

## Tests requeridos
- Plan `CALENDARIO`: asignar ubicación funciona igual que hoy.
- Plan `CONTADOR`: no se puede asignar ubicación; el mensaje es claro.
- Plan `CONTADOR` con ubicaciones preexistentes: la pantalla `Ver` las señala; no se rompe nada.
- La asignación de **equipos** a planes por contador sigue funcionando sin cambios.
